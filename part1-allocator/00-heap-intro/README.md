# heap-intro

프로세스의 메모리 영역 중 힙 영역에 대해 알아보고, 
힙 메모리 할당과 해제 방법(사용자 관점), gdb에서 힙 메모리를 관찰하는 방법에 대해 다룬다.

자세한 내용은 이 문서에서 다루지 않는다.

---

## 1. 힙(Heap) 영역

프로세스의 메모리는 다음 5개의 영역으로 나눌 수 있다.

- Text(Code) 영역: 실행할 기계어 명령어들. 읽기 전용.
- Data 영역: 초기화된 전역/정적 변수.
- BSS 영역: 초기화 안 된 전역/정적 변수. 실행 시 0으로 초기화 됨.
- Heap 영역: 동적으로 할당하는 메모리.
- Stack 영역: 함수 호출 스택, 지연 변수.

가상 메모리 상으로는 대략 다음과 같은 배치를 가진다.

```
높은 주소
+-------------+
|   Stack     | ↓ 아래로 자람
+-------------+
|             |
+-------------+
|   Heap      | ↑ 위로 자람
+-------------+
|    BSS      |
+-------------+
|    Data     |
+-------------+
|    Text     |
+-------------+
낮은 주소
```

# 2. 메모리의 할당과 해제

## 2.1 메모리 할당

### malloc

``` c
void *malloc(size_t size);
```

- `size` 바이트만큼 힙에서 메모리를 할당해 달라고 요청.
- 성공하면 그 메모리의 시작 주소(포인터) 반환, 실패하면 NULL.
- 초기화를 하지 않음 : 할당된 메모리 안에 쓰레기값이 들어있을 수 있음.

### calloc

``` c
void *calloc(size_t nmemb, size_t size);
```

- `size` 바이트 크기의 메모리 `nmemb` 개를 할당 : 총 `size` * `nmemb` 바이트 할당.
- 0으로 초기화 함.

### realloc

``` c
void *realloc(void *ptr, size_t size);
```

- 이미 할당된 `ptr` 메모리를 `size` 크기로 재조정
- 기존 데이터는 최대한 유지, 필요 시 다른 위치로 옮기고 기존 위치는 알아서 해제

## 2.2 메모리 해제

``` c
void free(void *ptr);
```

- `ptr`이 가리키는 메모리를 힙 allocator한테 반납.
- 반납된 메모리는 물리적으로 지워지는 것이 아니라, allocator가 다시 쓸 수 있는 블록으로 관리 목록에 추가함.
- 데이터 자체는 그대로 남아있을 수 있음.

# 3. gdb

플러그인 없이 gdb만으로 실습을 진행할 예정이다.

### gdb 기본 명령어

```
b main          # 브레이크포인트
r               # 실행
n / s           # 한 줄 실행 (n: step over, s: step into)
c               # 계속 실행
p 변수          # 변수 값 확인
p/x 변수        # hex로 확인
```

### 메모리 맵 확인 (heap 위치 확인)

```
info proc mappings
```

프로세스의 메모리 영역 목록이 출력된다. </br>
여기서 `[heap]`이라고 표시된 줄에서 힙의 시작/끝 주소를 알 수 있다.

### 메모리 값 읽기 (`x` 명령어)

포맷: `x/[개수][단위][표시형식] <주소>`

- 단위: `b`(1바이트), `h`(2바이트), `w`(4바이트), `g`(8바이트)
- 표시형식: `x`(hex), `d`(decimal), `s`(문자열), `i`(명령어)

예시: 
```
x/4gx ptr-0x10     # ptr 기준 16바이트 앞부터 8바이트씩 4개(=32바이트) hex로
x/20gx $rsp        # 스택 확인할 때도 동일한 방식
x/s ptr            # 문자열로 보기
```

### 청크 구조를 손으로 읽는 법

64비트 기준 chunk 레이아웃 (추후 자세히 다룰 예정):

```
chunk 시작 주소
+-----------------------+
|  prev_size (8바이트)  |  ← 이전 청크가 free 상태일 때만 의미 있음
+-----------------------+
│  size (8바이트)       │  ← 실제 청크 크기 + flag 비트 3개
+-----------------------+  ← malloc이 반환하는 포인터가 가리키는 지점
|                       |
|                       | 
|  user date            |
|                       |
|                       |
+-----------------------+
```

즉 `malloc()`이 리턴한 포인터를 `ptr`이라고 하면:

```
x/2gx ptr-0x10
```

이렇게 하면 `ptr-0x10`(=prev_size)부터 8바이트씩 2개, 즉 `prev_size`와 `size` 필드를 한 번에 볼 수 있다.


### 실습 시 기본 조합

```
b main
r
n (malloc 호출까지 진행)
p ptr                  # malloc이 리턴한 주소 확인
x/2gx (long)ptr-0x10   # 청크 헤더(prev_size, size) 확인
x/8gx (long)ptr-0x10   # 헤더 + user data 앞부분까지 좀 더 넓게 보기
```

# 4. 실습

짧은 실습 코드를 컴파일한 뒤, gdb를 활용해 메모리 할당/해제 함수 호출 시의 어셈블리와 할당 전후의 메모리를 확인한다.

## 실습 환경

- Ubuntu 20.04
- glibc 2.31
- 64bit

실습 결과는 glibc 버전에 따라 달라질 수 있다.
본 문서는 Ubuntu 20.04의 glibc 2.31을 기준으로 한다.

편하게 실습을 하고 싶다면 gdb 내에서 ASLR을 끄는 것을 추천한다.

```
(gdb) set disable-randomization on
(gdb) show disable-randomization
Disabling randomization of debuggee's virtual address space is on.
```

## 4.1 실습 코드

``` c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    char *p1;
    int *p2;
    char *p3;

    // malloc
    p1 = malloc(0x20);
    if (p1 == NULL) {
        perror("malloc");
        return 1;
    }

    strcpy(p1, "hello heap");
    printf("p1 = %p, data = %s\n", (void *)p1, p1);

    // calloc
    p2 = calloc(8, sizeof(int));
    if (p2 == NULL) {
        perror("calloc");
        free(p1);
        return 1;
    }

    printf("p2 = %p\n", (void *)p2);
    printf("p2[0] = %d\n", p2[0]);

    // realloc
    p3 = realloc(p1, 0x40);
    if (p3 == NULL) {
        perror("realloc");
        free(p1);
        free(p2);
        return 1;
    }

    p1 = p3;

    strcat(p1, " - realloc");
    printf("p1 after realloc = %p, data = %s\n",
           (void *)p1, p1);

    // free
    free(p1);
    free(p2);

    return 0;
}
```

### 실행 확인

```
(gdb) r
Starting program: /heap-lab/part1-allocator/00-heap-intro/sample231
p1 = 0x5555555592a0, data = hello heap
p2 = 0x5555555596e0
p2[0] = 0
p1 after realloc = 0x555555559710, data = hello heap - realloc
```

## 4.2 어셈블리

우선 소스코드가 컴파일 되었을 때, 어셈블리는 어떻게 나타나는지 살펴본다.

### malloc

``` c
    // malloc
    p1 = malloc(0x20);
```

이는 어셈블리로 다음과 같이 나타난다.

```
   0x00000000000011f5 <+12>:    mov    edi,0x20
   0x00000000000011fa <+17>:    call   0x10d0 <malloc@plt>
   0x00000000000011ff <+22>:    mov    QWORD PTR [rbp-0x18],rax
```

SysV AMD64(x86_64 Linux) 호출 규약에 따라 `edi`에 `malloc`에 전달할 인자 0x20을 저장하고, 
`rax`를 반환값으로 전달하고 있는 것을 확인할 수 있다. 
그리고 스택(`p1`)에 반환값을 저장하고 있다.

포인터 변수 p1은 스택에 있으며, p1이 담고 있는 값은 `malloc`으로 할당받은 힙 영역의 메모리 주소이다. 

> **노트 ─ 반환값**
> 
> `malloc`이 반환하는 값은 힙 청크의 시작 주소가 아닌, 힙 청크 내부의 유저 데이터 시작 주소이다. 
> 이에 대해서는 다음 장에서 더 자세히 다룰 예정이다.

### calloc

```
    // calloc
    p2 = calloc(8, sizeof(int));
```

```
   0x0000000000001257 <+110>:   mov    esi,0x4
   0x000000000000125c <+115>:   mov    edi,0x8
   0x0000000000001261 <+120>:   call   0x10c0 <calloc@plt>
   0x0000000000001266 <+125>:   mov    QWORD PTR [rbp-0x10],rax
```

`calloc`도 `malloc`과 유사하게 나타난다. 

### realloc

```
    // realloc
    p3 = realloc(p1, 0x40);
```

```
   0x00000000000012c4 <+219>:   mov    rax,QWORD PTR [rbp-0x18]
   0x00000000000012c8 <+223>:   mov    esi,0x40
   0x00000000000012cd <+228>:   mov    rdi,rax
   0x00000000000012d0 <+231>:   call   0x10e0 <realloc@plt>
   0x00000000000012d5 <+236>:   mov    QWORD PTR [rbp-0x8],rax
```

우선 `p1`(rbp-0x18) 이 담고 있는 값을 rax에 저장한다. 이때 rax에 담긴 값은 처음 `malloc`으로 할당받은 메모리의 주소가 된다. 
그리고 호출 규약에 따라 esi, rdi에 인자값을 담아 `realloc`에게 전달한다.

## 4.3 메모리 확인

이제 메모리가 할당/해제되었을 때 메모리가 어떻게 나타나는지 알아보자.

관찰 포인트는 다음과 같다.

1. 할당 직후 메모리 확인: 반환값(할당 주소)이 저장된 `rax` 기준
2. 프로그램 출력값으로 나온 주소 확인: 반환값과 비교
3. 할당받은 메모리에 데이터가 기록되는 위치 확인
4. 해제 직후 메모리 확인: 할당 전과 비교

### malloc

`malloc()` 호출 직후:

```text
(gdb) x/6gx $rax-0x10
0x555555559290: 0x0000000000000000      0x0000000000000031
0x5555555592a0: 0x0000000000000000      0x0000000000000000
0x5555555592b0: 0x0000000000000000      0x0000000000000000
```

`malloc()`이 반환한 주소는 `0x5555555592a0`이다.

`malloc()`은 chunk 전체의 시작 주소가 아니라, 사용자 데이터 영역의 시작 주소를 반환한다.

따라서 `0x10`바이트 앞에서 메모리를 확인하면 chunk 헤더를 관찰할 수 있다.

출력값 확인:

```text
(gdb) c
Continuing.
p1 = 0x5555555592a0, data = hello heap
```

프로그램에서 출력한 주소와 `rax`에 저장된 주소가 동일한 것을 확인할 수 있다.

데이터 기록 위치 확인:

```text
(gdb) x/4gx 0x555555559290
0x555555559290: 0x0000000000000000      0x0000000000000031
0x5555555592a0: 0x6568206f6c6c6568      0x0000000000007061
```

문자열 `"hello heap"`이 `0x5555555592a0`부터 저장된 것을 확인할 수 있다.

### calloc

`calloc()` 호출 직후:

```text
(gdb) x/4gx $rax-0x10
0x5555555596d0: 0x0000000000000000      0x0000000000000031
0x5555555596e0: 0x0000000000000000      0x0000000000000000
```

프로그램 출력:

```text
p2 = 0x5555555596e0
p2[0] = 0
```

`calloc(8, sizeof(int))`은 총 32바이트를 할당한다.

`calloc()`은 메모리를 0으로 초기화하므로, 메모리 내용과 `p2[0]`의 값이 모두 0인 것을 확인할 수 있다.

### realloc

`realloc()` 호출 직후:

```text
(gdb) x/10gx $rax-0x10
0x555555559700: 0x0000000000000000      0x0000000000000051
0x555555559710: 0x6568206f6c6c6568      0x0000000000007061
0x555555559720: 0x0000000000000000      0x0000000000000000
0x555555559730: 0x0000000000000000      0x0000000000000000
0x555555559740: 0x0000000000000000      0x0000000000000000
```

프로그램 출력:

```text
p1 after realloc = 0x555555559710, data = hello heap - realloc
```

데이터 기록 위치 확인:

```text
(gdb) x/10gx 0x555555559700
0x555555559700: 0x0000000000000000      0x0000000000000051
0x555555559710: 0x6568206f6c6c6568      0x616572202d207061
0x555555559720: 0x00000000636f6c6c      0x0000000000000000
0x555555559730: 0x0000000000000000      0x0000000000000000
0x555555559740: 0x0000000000000000      0x0000000000000000
```

`realloc()` 이후 메모리 주소가 `0x5555555592a0`에서 `0x555555559710`으로 변경되었다.

기존 데이터인 `"hello heap"`은 유지되었으며, 새로운 문자열 `" - realloc"`이 추가된 것을 확인할 수 있다.

`realloc()`은 상황에 따라 기존 메모리를 확장할 수도 있고, 새로운 위치에 메모리를 다시 할당할 수도 있다. 
`realloc()`이 새로운 위치에 메모리를 다시 할당하면 기존 메모리는 자동으로 해제된다. 
따라서 이 시점에서 처음 `p1 = malloc(0x20)`으로 할당받은 메모리는 해제되어 있다.

해제된 (old)p1:

```text
(gdb) x/4gx 0x555555559290
0x555555559290: 0x0000000000000000      0x0000000000000031
0x5555555592a0: 0x0000000000000000      0x0000555555559010
```

메모리를 해제한 이후에도 메모리 영역 자체가 즉시 사라지는 것은 아니다. 
메모리 내용이 변경된 것을 확인할 수 있으며, 해제된 메모리는 allocator가 다시 사용할 수 있도록 관리된다.

### free(p1)

`free(p1)` 호출 이전:

```text
(gdb) x/10gx 0x555555559700
0x555555559700: 0x0000000000000000      0x0000000000000051
0x555555559710: 0x6568206f6c6c6568      0x616572202d207061
0x555555559720: 0x00000000636f6c6c      0x0000000000000000
0x555555559730: 0x0000000000000000      0x0000000000000000
0x555555559740: 0x0000000000000000      0x0000000000000000
```

`free(p1)` 호출 이후: 
```
(gdb) x/10gx 0x555555559700
0x555555559700: 0x0000000000000000      0x0000000000000051
0x555555559710: 0x0000000000000000      0x0000555555559010
0x555555559720: 0x00000000636f6c6c      0x0000000000000000
0x555555559730: 0x0000000000000000      0x0000000000000000
0x555555559740: 0x0000000000000000      0x0000000000000000
```

### free(p2)

`free(p2)` 호출 이전:

```text
(gdb) x/4gx 0x5555555596d0
0x5555555596d0: 0x0000000000000000      0x0000000000000031
0x5555555596e0: 0x0000000000000000      0x0000000000000000
```

`free(p2)` 호출 이후:

```text
(gdb) x/4gx 0x5555555596d0
0x5555555596d0: 0x0000000000000000      0x0000000000000031
0x5555555596e0: 0x00005555555592a0      0x0000555555559010
```

`free()` 이후 메모리의 내용이 변경된 것을 확인할 수 있다.

이는 메모리가 즉시 제거되는 것이 아니라, allocator가 내부적으로 관리하는 구조에 포함되기 때문이다.

`free()` 이후 메모리에 어떤 값이 기록되는지에 대한 자세한 내용은 이후 장에서 다룬다.

# 5. 정리

# 5. 정리

이번 장에서는 힙 영역의 기본 개념과 사용자 관점에서의 메모리 할당/해제 방법, 그리고 gdb를 이용해 힙 메모리를 직접 관찰하는 방법을 간단히 살펴보았다.

- 힙은 프로그램 실행 중 필요한 크기의 메모리를 동적으로 할당하기 위해 사용하는 영역이다.
- `malloc()`은 지정한 크기의 메모리를 할당하고, `calloc()`은 메모리를 할당한 뒤 0으로 초기화한다.
- `realloc()`은 기존 메모리의 크기를 변경하며, 필요하면 새로운 위치에 메모리를 할당하고 기존 데이터를 옮긴 뒤 이전 영역을 해제한다.
- `free()`는 메모리를 삭제하는 것이 아니라 allocator에게 반환한다. 따라서 해제 이후에도 기존 데이터가 일부 남아 있거나 allocator의 관리 정보로 덮어써질 수 있다.
- `malloc()` 계열 함수가 반환하는 포인터는 chunk 자체의 시작 주소가 아니라 user data 영역의 시작 주소이다.
- 64비트 glibc 환경에서는 반환된 포인터의 `0x10`바이트 앞을 확인하여 기본적인 chunk header를 관찰할 수 있다.
- gdb의 `x` 명령어를 이용하면 별도의 heap 플러그인 없이도 chunk header와 user data를 직접 확인할 수 있다.
- `info proc mappings`를 이용하면 실제로 할당된 주소가 `[heap]` 영역 내부에 존재하는지 확인할 수 있다.

이번 실습에서는 `malloc`, `calloc`, `realloc`, `free` 호출 전후의 메모리를 직접 비교했다.

특히 `realloc()`에 의해 주소가 변경되면서 기존 데이터가 새로운 영역으로 이동하는 모습과, `free()` 이후 user data 영역의 내용이 변경되는 모습을 확인할 수 있었다.

아직 `size` 필드의 정확한 의미, chunk 크기 계산 방식, `free()` 이후 기록되는 값의 의미 등은 다루지 않았다.

이후 장에서는 이러한 메모리 구조와 allocator 내부 동작을 조금씩 자세히 살펴본다.
